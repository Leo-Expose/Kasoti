# KASOTI — SPECIMEN mock-card print specification (M0.6)

**This is a specification, not artwork.** No finished design files live in this
folder. Producing the print masters is design work with its own owner
(docs/HANDOFF.md §2 — Demo/Docs/QA with Design); what lives here is the brief
that says exactly what those masters must contain so that a designer, or a
teammate with a vector editor and three hours, produces something the pipeline
can actually parse, challenge and print.

Derived from DATA.md §2. Read DATA.md §2 alongside this file; this document
expands it, it does not replace it.

---

## 0. The one non-negotiable

**Everything printed here carries a big diagonal `SPECIMEN — KASOTI TEST`.**

Not a legal formality — an operational one. At the finals a judge hands us
whatever is in their pocket (DEMO.md §3: "Judge handed ANY printout → classify
live"). Anything that could be mistaken for a genuine identity document must be
unmistakably fake before it leaves our hands. See DATA.md §1: no real-PII pixels
leave a consent boundary.

Design requirements for the watermark:

- diagonal, bottom-left → top-right, **high contrast but low opacity** so the
  OCR path still reads the underlying fields (we want to exercise MRZ/QR/VIZ
  parsing, not the watermark)
- crosses the **photo box and the MRZ band**, not just a corner — a corner
  watermark survives cropping
- rendered at print resolution, not screen resolution
- **not** removable by trimming: keep it ≥ 15 mm inside every trim edge
- repeat the same string in the card footer at 8 pt, horizontal

## 1. The four tracks

Four watermarked tracks (DATA.md §2). Each exists to drive a specific set of
pipeline layers (FUSION.md §7 marks each layer ● load-bearing / ○ auxiliary).

| # | Track | Card name used | Layers it must exercise | Layers it must NOT fake |
|---|---|---|---|---|
| T1 | passport-datapage-like | ICAO 9303 TD3 **MRZ band, 2 lines × 44 chars** | MRZ parse + 7-3-1 check digits ●, face 1:1 ●, macro ●, diary ● | **no chip** — NFC is P1 and stubbed; if a chip is drawn, the app will try BAC and we will demo a fallthrough |
| T2 | aadhaar-like | **QR block** carrying a payload signed by a **TEST keypair** | signed-QR verify ●, Verhoeff ●, macro (PVC honesty rule) ●, face ● | **no production UIDAI key, ever.** prod-key slots stay EMPTY with a rotation-doc pointer (DATA.md §7) |
| T3 | voter-like | format validators (dates, name/DOB block) | date/format logic ○, face ●, macro ● | no MRZ, no signed QR — this is the **unsigned-QR / no-math** track |
| T4 | paper-nagarikta-like (paper ID) | copy/photocopy detect | macro ○+copy-detect, face ●, diary ● | no QR, no MRZ — this is the track where **a photocopy of a genuine** is the interesting attack |

### 1.1 T1 — passport-datapage-like

Elements, in reading order:

1. **Header band** — issuing-state style block, title line, document type code
   in the two-letter ICAO form.
2. **VIZ data block** — surname, given names, nationality, DOB, sex, place of
   birth, issue/expiry dates, document number, MRZ identifier line. Typeset
   exactly as an MRZ transliteration is defined: uppercase A–Z only, no
   diacritics, no punctuation.
3. **Photo box** — see §2. The photo must be a **consented teammate face**
   (DATA.md §4) or a public-set face with its licence noted. Never a
   third-party or a scraped face.
4. **MRZ band** — 2 lines × 44 characters, OCR-B font metrics:
   - line 1: `P<ISSUER><GIVEN NAME><<<SURNAME<<<<<<<<<<<<<<<<<<<<<` (44 ch)
   - line 2: doc number + check digit, nationality, DOB + check digit, sex,
     expiry + check digit, optional data + check digit, final composite check
     digit
   - **The check digits must be real**, computed with the same generator the
     app uses (`:core` MRZ builder, seeded — DATA.md §7). A card with a wrong
     check digit trains the team to ignore R-MATH-01.
   - Must survive MRZ-line cropping: no descenders, no kerning tricks, uniform
     stroke, minimum 1.2 mm cap height, high contrast, **no background
     pattern behind the MRZ band** (guilloche over an MRZ is a real-world
     problem we can test separately, not a default).
5. **Optional chip contact pad** — T1 is the only track where a chip pad is
   drawn. Draw it as a plain contact pad, leave it dead. Do not print "ePassport"
   in a way that implies we read it.

### 1.2 T2 — aadhaar-like

1. **Header band** — title block.
2. **VIZ fields** — name, DOB, gender, a **12-digit number whose last digit is a
   real Verhoeff check digit** (FR-M3, `dev.kasoti.checks.Verhoeff`).
3. **Photo box** — see §2.
4. **QR block** — minimum 25 × 25 mm, quiet zone ≥ 4 modules, error correction
   **M or higher** (it has to survive an inkjet reprint; this is the substrate
   the macro layer is judging).
   The payload must be **generated by the test keypair** and signed. Ship the
   vectors in `eval/fixtures/` (DATA.md §7). Mutants for the red team — one per
   failure mode — are generated from the same pipeline, not hand-edited.
5. **PVC honesty rule** — this track is the one where macro → A-PROC-01 matters
   most (FUSION.md §7: macro ●, "PVC honesty rule"). Print at least one copy on
   a real PVC card if you can source one; the laminate-vs-PVC difference is the
   point of the track.

### 1.3 T3 — voter-like

1. Header band.
2. **VIZ fields** — elector name, father's/husband's name, DOB, gender, address
   block, elector ID with a **format-valid check character** (FR-M3).
3. Photo box.
4. A **small unsigned QR** (deliberately unsigned, FR-Q2) — this is the track
   that proves the app labels an unsigned QR `UNSIGNED` and routes it to
   A-QR-01 rather than treating it as verified.
5. No MRZ.

### 1.4 T4 — paper-nagarikta-like

1. Header band with a paper-flavoured visual (no plastic sheen in the design —
   it must be printable on ordinary office stock).
2. VIZ fields: name, DOB, document number, issue/expiry, a **place-of-issue
   field that varies between prints** so the photocopy test has something to
   diverge on.
3. Photo box.
4. **No QR, no MRZ, no chip.** The interesting artefacts for this track are
   **derived**: a photocopy of it, a phone-screen capture of it, an inkjet
   reprint of it. Those are the attack artefacts (RT-P3, RT-P4).
5. A **stamp box** — see §3.

## 2. Photo box (all tracks)

- size: **35 × 45 mm** on every track, identical across tracks so the face
  pipeline's crop geometry is exercised once, not four times
- the photo inside must be a **consented teammate face** or a public-set face
  with its licence recorded (DATA.md §4). Zero tolerance for scraped or
  third-party faces.
- include a **printed photo border / frame line** — the frame is a macro feature
  and a paste-swap boundary (AT-03, RT-S1). Paste swaps will be cut from the
  *edge* of this box, so the border must be visible at macro magnification.
- at least one set must have a **visibly different border thickness** across
  cards, so the classifier does not learn one border.
- glue-swappable: at least one spare printed set must be printed so the photo
  can be lifted and swapped with a single glue stick (DEMO.md §3 wants a
  pre-glued spare ready).

---

## 3. Stamp box (T1, T4 at minimum)

- size: **40 × 20 mm**, outlined box, empty on the clean master.
- Purpose: UV/fluorescence and macro texture inspection (SPEC: "Tampered
  stamps → zoom assist + UV + macro stamp texture"). The stamp layer is
  **manual zoom assist + auxiliary** (QA_BANK) — it is drawn here so the box
  exists and is scannable, not so the system can read it.
- produce a **stamp-ink variant set**: one red rubber-stamp look (inky, slight
  bleed at the edges), one photocopied grey version, one hand-drawn marker
  version (RT-S5). Three variants × the four tracks is the gallery you want.

---

## 4. Background: "guilloche-ish", drawn not copied

DATA.md §2 is explicit: **guilloche-ish background (drawn, not copied).**

- the pattern must be **original geometry** generated by the designer or by a
  script we write — never traced, scanned or reproduced from a genuine card
- it should be **non-periodic enough** that the macro classifier does not
  learn "this exact lattice = genuine". Use at least three distinct pattern
  families across the four tracks, and give each track a different screen
  angle (15° / 45° / 75°) — the screen angle is a real macro feature
  (hardware/calibration_card.pdf section E) and this is our chance to
  exercise it on print, not just on a card
- keep it **light**: the pattern must not degrade VIZ OCR. Low-ink coverage
  (visually ~10–20% coverage), no heavy black fills
- **no real emblem, no national crest, no government wordmark, no real
  ministry name.** Invent neutral issuing-authority names for all four tracks
  (e.g. "REPUBLIC OF KASOTIA — TEST AUTHORITY"). Using a real one is a
  different category of problem.

## 6. Print and produce

- **Layout proof** on an office laser, one set, before anything else (DATA.md
  §2). The point of the first print is to find out that the MRZ band is
  illegible at our capture resolution, not to look nice.
- **Production print**: 10 sets (DEMO.md §4) + **1 pre-glued spare** +
  the macro SOP reprints across substrates (DATA.md §3: inkjet, laser,
  photocopy, phone-screen capture).
- **Substrate spread is the point.** For each track produce at least:
  office laser (baseline), home inkjet, and a photocopy-of-a-print. Those
  three give the classifier its OFFSET / INKJET / PHOTOCOPY separation
  (DATA.md §3 labels).
- Do **not** laminate the clean masters — laminate is an attack surface
  (AT-03 tape-laminate swap, RT-S2) and only the attack artefacts should have
  it.
- Print on ordinary 80 gsm office stock unless the track specifically needs
  PVC (T2's PVC honesty rule).

## 7. Acceptance checklist before a SPECIMEN set is used on stage

- [ ] All four tracks present, each watermarked diagonal **and** footer
- [ ] MRZ check digits verified by the `:core` MRZ builder, not by eye
- [ ] Verhoeff digit on T2 verified by `dev.kasoti.checks.Verhoeff`
- [ ] QR payload signature verified against the **TEST** public key
- [ ] no production key material anywhere in the artwork or the QR payloads
- [ ] no third-party face anywhere; consent records filed offline (DATA.md §6)
- [ ] photo boxes crop cleanly through the app's face geometry
- [ ] background patterns are original and differ in angle per track
- [ ] at least one inkjet reprint and one photocopy per track exist for the
      live macro demo (DEMO.md §3 needs genuine vs inkjet side by side)
- [ ] one pre-glued photo-swap spare exists and has been tested
- [ ] `eval/data/**/manifest.csv` rows added with the DATA.md §3 field set,
      including `calib-id`
- [ ] nothing that could read as a real document escaped this repository
